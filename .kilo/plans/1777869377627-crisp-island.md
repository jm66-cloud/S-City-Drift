# S市漂模拟经营游戏 — 完整实施计划

## 1. 游戏设计总览

### 灵感来源
- **《不要喂猴子》** — 电脑桌面模拟、多窗口管理、偷窥/监视玩法
- **像素美术风格** — 复古计算机界面，CRT 显示器氛围
- **S市漂题材** — 真实的中国都市生存体验

### 世界观
- 你是刚来到申海市的年轻人，带着 **10 万元** 蜗居在出租屋
- 唯一的资产是一台老旧电脑，决定通过 **炒股** 改变命运
- 你需要平衡 **日常生活**（吃饭、睡觉、恋爱）与 **股票交易**（8:00-18:00）
- 积累资本后 **买房买车**，**创办公司**，做大做强，最终 **IPO 上市**
- 在这座城市里，你要面对 **人情世故、商场暗战、甚至法律的边界**
- 你的 **心理健康** 同样重要——过度压力会导致崩溃，学会放松才能走得更远
- 多条人生路径可选：股神、地产大亨、隐居田园，不只有 IPO 一条路

### 核心循环
```
7:00 起床 ← 阅读晨间新闻（新闻App推送）
  ↓
7:00-8:00 吃饭、洗漱、看新闻（生活面板 + 新闻App）
  ↓
8:00 开盘（交易开始！根据新闻判断买卖方向）
  ↓ 盯盘、交易、管理公司、跟阿强聊股票
18:00 收盘
  ↓
18:00-?? 管理公司、社交聊天、约会、看房、买车
  ↓
23:00前 睡觉（生活面板 → 时间快进到次日7:00）
  ↑________________ 24分钟 = 1天 ________________↓
```

### 2.9 技术实现关键决策

#### 2.9.1 增量时间引擎（Delta Time）

**问题**：`setInterval` 在标签页非激活、CPU 高负载时会延迟或停止，游戏时间与现实脱节。

**方案**：所有时间计算基于 `performance.now()` 真实时间戳：
```javascript
let lastTime = performance.now();
function gameLoop(now) {
  const deltaMs = now - lastTime;       // 真实经过的毫秒数
  lastTime = now;
  if (!paused) {
    const gameMinutes = deltaMs / 1000;  // 1真实秒 = 1游戏分
    TimeEngine.advance(gameMinutes);
    StockEngine.update(gameMinutes);
    BotEngine.update(gameMinutes);
  }
  requestAnimationFrame(gameLoop);
}
```
- 暂停时 `deltaMs` 不累加，时间完全冻结
- 切换标签页回来后，正确补上经过的时间（一次性消化多个游戏分）
- 倍速时：`gameMinutes = deltaMs / 1000 * speedMultiplier`

#### 2.9.2 分层更新与性能优化

150 支股票 + 20 Bot 的每秒全量更新不可行。采用分层策略：

| 层级 | 更新频率 | 范围 | 内容 |
|------|---------|------|------|
| L1 | **每帧（实时）** | 玩家自选股 + 持仓股 | 实时价格、盘口、K线 |
| L2 | **每 5 秒** | 热门股（涨幅榜 top20）| 价格、成交量 |
| L3 | **每 30 秒** | 剩余股票 | 简化随机游走 |
| Bot | **每 10 秒** | 20 个 Bot | 决策+下单 |
| 撮合 | **事件驱动** | 仅玩家/Bot下单时 | 触发撮合逻辑 |

- Canvas K 线图使用**离屏渲染** + 脏矩形（仅更新变化区域）
- 所有窗口 DOM 操作使用 `requestAnimationFrame` 批量提交，避免强制回流

#### 2.9.3 撮合引擎简化策略

全功能连续竞价（价格优先+时间优先+多档订单簿）实现复杂且易错。采用**混合方案**：

- **玩家的市价单**：按当前市价立即成交（假设流动性充足），不进入订单簿排队
- **玩家的限价单**：进入简化订单簿，每隔 1 秒尝试撮合一次
- **Bot 的订单**：全部按市价立即成交（Bot 模拟真实交易者的挂单行为）
- **五档盘口**：由引擎根据当前买卖压力合成伪数据，非真实挂单
- **成交价**：由引擎内部公式决定（基本面 + 新闻 + 随机噪声 + Bot 需求），玩家订单按此价格成交

这样避免了复杂的撮合队列，同时保持了"能看到盘口、能下单"的核心体验。

#### 2.9.4 存储分层策略

| 数据类型 | 存储方案 | 理由 |
|---------|---------|------|
| 当前状态（角色/持仓/公司/时间）| **localStorage** | 快速读写，每次存档序列化 |
| K 线历史（150股×100根）| **IndexedDB** | 数据量大，异步读写不阻塞主线程 |
| 订单/成交记录 | **IndexedDB** | 最多 500 条/账户 |
| 聊天记录 | **IndexedDB** | 最多 200 条/联系人 |
| 新闻存档 | **localStorage** | 仅30天，数据量小 |
| 配置（AI key/设置）| **localStorage** | 独立 key，不参与存档 |

- IndexedDB 操作封装为 `async` 函数，游戏启动时异步加载历史数据
- 存档文件导出：将 IndexedDB + localStorage 数据打包为单个 JSON 下载
- 导入时自动校验数据完整性

#### 2.9.5 像素字体可读性

| 措施 | 说明 |
|------|------|
| 默认 16px | 点阵字体 `Zpix` 在 16px 下中文可读性最佳 |
| 大字体模式 | 设置中可选 20px，布局自动调整 |
| 文字描边 | 关键文本加 1px 黑色描边，抵消 CRT 模糊效果 |
| 高对比度 | 文本 `#c0c0c0` 在深色背景上保持清晰 |

#### 2.9.6 多语言规划

- **v1.0**：仅中文（繁体+简体根据浏览器语言自动切换）
- **v1.1+**：通过外部 JSON 语言包实现英文支持
- 所有 UI 文本在代码中使用 `i18n.get('key')` 函数包裹，后续只需翻译 JSON 文件即可添加新语言
- itch.io 页面提供中英文描述

## 5. 角色系统

### 5.1 角色属性

| 属性 | 说明 |
|------|------|
| 名称 | **自定义**（开局输入）|
| 现金 | 初始 10 万，含银行卡余额和证券账户 |
| 饱食度 | 0~100，每 **10 游戏分钟** -1，≤20 时操作效率 -50%，≤0 时晕倒 |
| 困意值 | 0~100，每 **10 游戏分钟** +0.5，≥80 时操作失误率 +30%，=100 时强制睡着 |
| **压力值** | **0~100，操作/亏损/犯罪/工作过度时上升，压力>70交易颤抖误操作，>90随机崩溃强制休息，=100住院** |
| 精力 | 0~100，饱食+睡眠+压力综合，影响工作效率/收益率 |
| 证券账户 | 开户后可用 |
| 持仓 | 持有股票列表 |
| 公司 | 拥有的公司（0 或 1 个）|
| 人际关系 | 各联系人好感度 + 宿敌「小赵」竞争状态 |

**压力来源与减压**：
```
压力 +3  → 持仓亏损 > 5%（每笔交易）
压力 +5  → 犯罪风险增加（每次操作）
压力 +8  → 连续 5 天没有休闲活动
压力 +20 → 被审计/警察调查
压力 +15 → 与恋人分手/吵架

减压 -10 → 看电影、逛街（约会操作）
减压 -15 → 按摩、健身（生活面板新增）
减压 -8  → 找阿强/小李聊天选择「倾诉」
减压 -5  → 购买减压物品（放在出租屋）
```

**衰减曲线**（1 游戏日内）：
```
        7:00  8:00           18:00        24:00   7:00
饱食:   100    90  (开盘)    70 (收盘)    60      → 睡觉 → 50(-10)
困意:   0      10  (开盘)    55 (收盘)    80      → 睡觉 → 0
```

## 6. 时间系统

### 6.1 时间流速

| 参数 | 值 |
|------|-----|
| 游戏日长 | **24 现实分钟 = 1 个完整游戏日（24 小时）** |
| 每秒对应 | **1 真实秒 = 1 游戏分钟** |
| 每分对应 | **1 真实分钟 = 1 游戏小时** |
| 交易时间 | **8:00 ~ 18:00**（10 游戏小时 = 10 现实分钟）|
| 休市时间 | **18:00 ~ 次日 8:00**（14 游戏小时 = 14 现实分钟）|
| 周末 | **不休市**，周一到周日全部正常交易 |
| 睡觉 | **玩家主动睡觉 → 时间快进到次日 7:00** |

**换算关系**：
```
完整一天：  24 现实分钟 = 1440 真实秒
1 游戏时：  1 现实分钟 = 60 真实秒
1 游戏分：  1 真实秒
交易时段：  8:00→18:00 = 10 游戏时 = 10 现实分钟
休市时段：  18:00→8:00 = 14 游戏时 = 14 现实分钟
```

**游戏时间演示范例**：
```
现实 0:00 → 游戏 8:00（开盘！）
现实 0:01 → 游戏 9:00
现实 0:05 → 游戏 13:00
现实 0:10 → 游戏 18:00（收盘）
现实 0:15 → 游戏 23:00
现实 0:20 → 游戏 4:00（玩家可睡觉）
现实 0:24 → 游戏 8:00（新一天开盘）
```

**暂停与倍速**：
- **暂停**（Space / 顶栏按钮）：冻结所有定时器，允许无压力查看窗口/下单
- **倍速选项**：
  - 交易时段（8:00-18:00）：仅限 1×（正常速度），防止影响交易公平
  - 休市时段/生活面板：1× / 2× / 4× 可选，加速跳过无聊等待
  - 睡觉时间快进：固定加速（不受倍速影响）

**睡觉机制**：
- 玩家在任意时间点击「睡觉」→ 弹窗确认 → 游戏时间快进到第二天 **7:00**
- 睡觉期间：饱食度 -10，困意值归零
- 醒来后：自动弹出「生活面板」提醒吃饭
- 如果玩家 **困意值 ≥ 80** 仍未睡觉：操作界面出现模糊/抖动效果，交易操作可能失败
- 如果困意值 = 100：**强制睡着**，自动快进到 7:00

**现实效果**：
- 交易时段（10分钟）：需要集中精力盯盘，股价每秒波动
- 休市时段（14分钟）：充裕时间管理公司、社交、吃饭、处理日常
- 每天一个完整的"交易→休整"周期，节奏清晰

**时间显示**：
```
桌面顶栏：  第 3 天  10:23:45  📈 盘中
            第 3 天  19:15:20  💤 盘后
状态栏：    饱食: 62%  困意: 45%  |  💰 ¥102,350
```

## 7. 核心系统设计

### 7.1 股市系统（StockEngine）

**150 支股票** × **11 行业**（同上一版方案）

**基本面价值系统**：
每支股票关联一个隐藏的**基本面分数**（0~100），作为股价的"锚点"：
- 初始分数由行业和随机种子决定（科技 40~80，金融 30~70 等）
- 分数缓慢变化：公司财报发布时 ±3~10，行业新闻 ±2~5，每 30 天自然波动 ±1~2
- **长期回归**：股价围绕 `基本面分数 × 2 元` 上下波动（±30% 范围）
- 玩家可在股票详情页查看：市盈率（PE）、市净率（PB）、营收趋势（简易折线图）

**股价生成算法**（每秒执行）：
```
基础价 = 基本面分数 × 2
趋势 = 基本面变化率 + 经济周期因子 + 行业联动因子
噪声 = 正态分布(0, σ)   // σ 随股票活跃度变化
新闻冲击 = 当日新闻影响（开盘时一次性计入）
Bot需求 = 所有 Bot 对该股净买入/卖出量（加权）

当前价 = 基础价 × (1 + 趋势 + 噪声) + 新闻冲击 + Bot需求影响
```

**日 K 线生成**：
- 每个交易日（10 分钟）生成一根日 K
- 开盘价 = 前一日收盘价
- 盘中波动：每秒更新，模拟分时走势
- 收盘价 = 最后一秒的价格 + 收盘集合竞价影响
- 最高价/最低价 = 盘中极值
- 成交量 = 当日累计撮合量

**周 K**：每 7 个交易日合并
**月 K**：每 30 个交易日合并
**分时图**：每秒价格记录，显示当日走势

**五档买卖盘口 + 深度图**（由引擎合成伪数据，基于当前买卖压力）

### 7.11 犯罪系统（CriminalEngine）

#### 7.11.1 犯罪类型

| 犯罪类型 | 条件 | 操作 | 收益 | 风险 | 后果 |
|---------|------|------|------|------|------|
| 挪用公款 | 必须创办公司 | 将公司账户资金转入个人银行卡 | 单次最多挪用公司现金的 50% | 每月审计概率 15%+累计次数×5% | 追回+罚款2倍+坐牢=游戏结束 |
| 内幕交易 | 公司已上市 | 在利好消息公布前买入自家股票 | 非法盈利 20%~50% | 证监会调查概率 8%+金额×0.1% | 没收非法所得+罚款3倍+市场禁入 |
| 财务造假 | 公司已上市 | 虚增营收 {X}%，降低税负 | 省税 10%~40% | 审计概率 10%+造假幅度×2% | 退市+罚款+坐牢 |
| 行贿官员 | 必须创办公司 | 支付 {X} 万换取审批加速/合同 | 缩短审批 50% | 举报风险 5%+金额×0.5% | 行贿罪+罚款5倍 |

#### 7.11.2 风险系统

- 每次犯罪操作生成一条 `CrimeRecord`
- 每月底触发风险判定：`Math.random() < baseRate + accumulatedRisk + (amount^0.5) * 0.01`
  - 金额越大，审计率指数级增长（平方根函数）
- 犯罪后即使未被发现，**恶名值** +5~20（视犯罪类型）
  - 恶名值 ≥ 50：供应商要求预付款，合作伙伴减少
  - 恶名值 ≥ 80：银行拒绝贷款，部分联系人拒绝聊天
- 玩家可以 **销毁证据**（花费 ¥10 万，降低 50% 累计风险）
- 玩家可以 **找人顶罪**（花费 ¥50 万，风险清零但恶名值 +10）
- 玩家可以 **洗钱**（花费犯罪金额的 20%，将非法所得变为合法收入，降低未来被追溯概率）
